## 新增测试未覆盖的实际路径

### 二次上机仍可跳过过渡

world_canvas.gd:1485 在非 USING 时清除 _member_using_tracker。正常换站经过走路/候课，故第二次 USING 时走的是新建 tracker 分支；该分支在 trained_ticks >= 4 时将进度置为 999。新增测试直接连续调用 helper 更换 device_id，保留了 tracker，绕过真实渲染清理路径。

对实际 helper 运行探针并重放上述清理步骤，结果为 FIRST=0、SECOND_AFTER_WALK=999。不是完整玩家操作复现，但与生产分支一致，足以证明当前测试覆盖不足。

修复：明确区分本次进入使用与存档恢复；不要通过累计训练量或剩余时间猜测进入原因。测试使用 USING→WALKING_TO/QUEUEING→USING 的完整状态序列，加入同设备再入场。

### 计时器受观察频率影响

相邻两次观察 tick 从 100 跳至 104，ticks_in_use 仅增加 1，探针输出 TICK_JUMP_100_TO_104=1。当前实现计算的是“观察到 tick 改变的次数”。低帧率、多 tick 合帧或一段时间未渲染时，过渡时长不再等于四个模拟 tick。

修复：用 tick 差值/明确的进入 tick 计算进度；暂停同 tick 不变；读档回退 tick 明确重建。补 100→104、重复同 tick、回退 tick 测试。

### 读档证据仍是模拟字典

新增“中途读档”断言构造 trained_ticks=50、remaining=20 后直接调用 helper，没有进行 SaveLoad 冷恢复/热恢复。clear_member_using_tracker 尚无生产调用。应检查真实恢复后缓存与复用 member_id 是否一致，再决定恢复即贴合还是保留过渡；两种策略均可，但须稳定且有清晰规格。
