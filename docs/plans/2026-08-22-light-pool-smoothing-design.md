# 灯光平滑化重构设计（2026-08-22）

## 问题

旧 `LightingLayer` 把像素风理解为逐像素 hash 缺口、颗粒簇和锯齿色阶。
光池、光束、暗角、窗光、环境回落和设备高光同时散点化，导致黄白颗粒混色，
也让干净的地板 tile 再次显脏。

## 设计

- 三盏吊灯各使用一个 104×72 的椭圆 PNG 光池，中心对齐各自 `landing`。
- 光池 RGB 固定为 `#F5D97B`，仅 alpha 以 smoothstep 径向渐变。
- 主光池间距 138px、宽 104px，水平净间隔 34px，不重叠。
- 落地灯缩放复用同一资产和色相，强度低于主吊灯。
- 吊灯到落点的投影光束使用解析式横向/纵向平滑衰减，不使用纹理噪声。
- 四周冷暗角使用到矩形边缘距离的 smoothstep 衰减，中心回到透明。
- 动态层只保留设备单像素受光边和 2×2 屏幕 emissive 点。
- 所有静态结果只由布局、资产和纯函数决定，无 RNG、无 hash。

## 资产管线

`tools/light_design/generate_light_pool.py` 使用 Pillow 生成
`assets/tiles/light_pool.png`。生成器验证单一非透明色相、alpha 范围和从中心到
边缘的单调衰减；运行时代码优先从 Godot 资源管线加载 PNG，并保留等价的干净
程序回退以支持缺失导入缓存的 headless 环境。

## 验证

- 单元测试覆盖 PNG 加载、尺寸、单一色相、96 级 alpha、中心/边缘关系、
  三灯位置和 34px 间隔、连续内核、平滑冷暗角、平滑光束及确定性。
- 旧 `_hash2`、分面灯池、散点 fade、环境散点、碎高光和散落屏幕 cluster
  方法均断言不存在。
- `tests/evidence/light-smooth-compare.png` 左侧为重构前，右侧为重构后。
