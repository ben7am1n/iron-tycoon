## 问题 A：上机过渡 —— ✅ 确证已按 09-09 要求修复

09-09 复评给出的修复要求是「以本次使用为单位的表现计时，独立处理上机、下机和取消/读档，不要靠重置真实训练计数来修动画」。当前代码符合该要求：

**实现位置**：`src/presentation/world_canvas.gd`
- `var _member_using_tracker: Dictionary = {}`（第 95 行）—— 表现层独立追踪器
- `_update_member_using_mount(member_id, target_inst_id, m, tick)`（第 1609 行）—— 唯一计时来源
- 调用点第 1529 行；`trained_ticks` **已完全不再参与过渡计算**，第 1633 行有显式注释说明这一点

**逐条对照 09-09 要求的四个场景**：

| 要求 | 实现 | 位置 |
|---|---|---|
| 散客首次上机平滑 | 首次进入 USING 一律 `ticks_in_use = 0` | 1631–1640 |
| 课程二次换站不跳过 | `device_id` 变化即重置为 0 并重设 `last_sim_tick` | 1613–1618 |
| 观察频率无关 | `dt = tick - last_sim_tick` 按模拟 tick 差值推进，不做帧计数 | 1620–1625 |
| 暂停冻结 | `dt == 0` 时严格不变（注释显式声明） | 1630 |
| 读档/回退不跳变 | `dt < 0` 显式重建 tracker 为 999；`notify_game_loaded()` 将恢复时处于 USING 的成员预置为 999 | 1626–1629、1658–1672 |

**测试覆盖确证**：`tests/integration/gym_adventure/visual_sample_test.gd` 第 159–232 行，8 个编号场景 / 9 条断言，与 09-09 要求的场景一一对应，其中两条是最关键的回归守卫：
- 第 196 行：`trained_ticks = 240` 的课程成员二次上机，`ticks_in_use` **仍必须为 0** —— 直接针对原缺陷
- 第 206 行：tick 从 120 回退到 90，tracker 干净重建为 999

**结论**：09-09 提出的具体缺陷已修复，且修复被真实测试覆盖，不是仅有提交信息。问题 A 关闭。
